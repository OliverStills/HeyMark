Security & Privacy

Version 1.1.0  ·  Last reviewed 2026-06-27

HeyMark converts PDF documents to Markdown in your browser. Your documents are never uploaded to any server. This page explains how that works, what it means in practice, and where the limits of that guarantee are.

The core claim

Your document is processed locally in your browser. HeyMark does not transmit the document or extracted content to our servers.

This is not a policy preference — it is an architectural constraint. HeyMark has no server-side application. There is nowhere to send documents to. The Content Security Policy enforced by the browser independently blocks any connection to a third-party origin, even if application code attempted one.

We verify this claim with automated Playwright tests that intercept every network request during a complete conversion cycle and fail if any request goes beyond the HeyMark origin.

How local processing works

When you open HeyMark, your browser downloads the app shell, JavaScript, fonts, and libraries from heymark.io. After that initial load, no further network activity is required.

When you convert a PDF:

  1. Your browser reads the file into memory using the FileReader API.
  2. pdf.js — a PDF library running as a Web Worker in your browser — parses the document.
  3. For text PDFs: text and layout data are extracted locally and reconstructed into Markdown.
  4. For scanned PDFs: each page is rendered to a canvas, then Tesseract.js — an OCR engine running as a local WebAssembly Web Worker — recognizes the text.
  5. The Markdown result is displayed in your browser.

Every step runs on your device. No step sends anything over the network.

Network requests

On page load

Your browser requests the following from heymark.io: the HTML page, CSS stylesheet, application JavaScript, fonts, vendor libraries (pdf.js, Tesseract.js, JSZip), WebAssembly files, and the OCR language data. These are static files. They are cached after the first visit.

During conversion

Zero. The conversion runs entirely on data already in memory.

On integrity verification

If you click VERIFY in the footer, HeyMark re-fetches each runtime asset from the same origin to hash and compare against the published manifest. No document content is involved.

How to confirm this yourself

Open DevTools (F12), go to the Network tab, upload a PDF, and convert it. Every request should go only to heymark.io (or heymark.pages.dev). There should be zero requests to any other origin during or after conversion.

What is not collected

HeyMark does not collect:

  • Your documents
  • Extracted document text
  • OCR output
  • Generated Markdown
  • Filenames or document metadata
  • Usage patterns or analytics
  • Session data or user identifiers

There is no analytics code, session recording, remote error logging, or advertising in HeyMark. The static analysis test suite checks the source code for tracking calls on every commit.

Memory and cleanup

While a conversion is running, the document exists in browser memory as an ArrayBuffer. After conversion, when you reset the app or start a new file, HeyMark:

  • Terminates the pdf.js and Tesseract Web Workers
  • Revokes all object URLs (URL.revokeObjectURL)
  • Clears the file input and removes queue entries
  • Drops references to the source buffer, extracted text, and generated Markdown

HeyMark does not claim to forensically wipe memory — the browser manages physical memory. What HeyMark does is drop all JavaScript references to document data so the garbage collector can reclaim it.

HeyMark does not store document content in localStorage, sessionStorage, IndexedDB, or any other persistent browser storage.

Downstream tool handoff

HeyMark's guarantee covers the conversion step only. Once you copy or download the Markdown, it is no longer under HeyMark's control.

If you paste the Markdown into a cloud editor, email client, AI assistant, or collaboration tool, that tool's privacy policy governs what happens to it. Choose downstream tools appropriate for the sensitivity of your documents.

HeyMark displays a reminder when you copy output from a scanned document.

Verifying what runs in your browser

Click VERIFY in the app footer. HeyMark will re-fetch every runtime file, hash the raw bytes using the browser's SubtleCrypto API, and compare each against the published manifest. A match means the code running in your browser is byte-for-byte identical to the published release.

The manifest's own SHA-256 is published in each GitHub release ↗, so you can independently confirm the manifest has not been altered.

Manual verification

Clone the repository, check out the release tag shown in the footer, run node build-hashes.mjs, and compare the output to the release-hash.json served by the site.

Hosting and subprocessors

HeyMark is hosted on Cloudflare Pages, which delivers the static files to your browser. Cloudflare does not receive document content. It receives standard CDN request logs: your IP address, the path requested, your user-agent string, and the HTTP response code.

No other subprocessor is involved. No subprocessor receives document content, extracted text, or generated Markdown. Full statement: SECURITY/SUBPROCESSORS.md ↗

Known limitations

HeyMark's local-processing guarantee has real boundaries:

  • Browser extensions — Extensions installed in your browser can read page content, including Markdown output. Use a profile without extensions for sensitive documents.
  • Compromised device — If your device has malware, a keylogger, or remote access software, an attacker can observe document content regardless of how HeyMark handles it. Endpoint security is outside HeyMark's control.
  • Post-export handling — Once you copy or download the Markdown, its privacy depends entirely on the tools you use with it.
  • Clipboard — Clipboard content can be read by other applications on your device. Clear the clipboard after pasting sensitive content.
  • No audit trail — HeyMark has no user accounts and keeps no log of conversions. This is a privacy feature, but it means there is no access audit for compliance purposes.
  • No penetration test — Security controls are self-assessed and backed by automated tests. An independent third-party pen test has not been conducted.
  • OCR accuracy — Scanned document OCR quality depends on scan quality. Review output before use in legal proceedings.
